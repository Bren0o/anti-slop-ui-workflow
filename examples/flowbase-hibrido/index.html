§ 01

Do commit ao deploy em um arquivo.

Você descreve os jobs. O FlowBase decide a ordem pelas dependências, cacheia o que se repete e roda em paralelo o que dá.

  1. Conecte o repositório

    GitHub, GitLab ou Bitbucket. Cada push abre um run; cada pull request recebe o status na própria PR. Nada de token copiado à mão.

  2. Aceite o flowbase.yml sugerido

    Lemos o lockfile, detectamos a stack e geramos o arquivo. Jobs com needs viram um grafo; sem needs, rodam juntos. Não existe segunda sintaxe para "avançado".

  3. Faça push e leia o log

    Quando um job falha, o trecho da falha vem primeiro, com arquivo e linha linkados ao commit. Todo merge na main faz deploy. Só isso.

flowbase.yml10 linhas
image: node:22
cache: auto        # detecta o lockfile
jobs:
  install:   { run: pnpm install --frozen-lockfile }
  lint:      { needs: [install], run: pnpm lint }
  typecheck: { needs: [install], run: pnpm tsc --noEmit }
  test:
    needs: [install]
    matrix: { filter: [checkout, catalog, auth] }
    run: pnpm test --filter ${{ matrix.filter }}
  deploy-staging: { needs: [lint, typecheck, test], only: main, run: ./deploy.sh }

§ 04

Perguntas que chegam no suporte.

Preciso migrar meus workflows existentes?

Não. O FlowBase roda ao lado do que você já tem. Muitos times começam rodando só os testes e migram o deploy depois.

O que acontece quando estouro os minutos do plano Grátis?

Os runs entram em fila até o mês virar. A gente avisa por e-mail aos 80% e aos 100%; nada é cobrado sem você mudar de plano.

Dá para rodar Docker, Go, Python, Rust?

Sim. cache: auto reconhece pnpm-lock.yaml, poetry.lock, go.sum e Cargo.lock. Para o resto, você indica a pasta de cache.

Onde ficam os secrets?

Criptografados por ambiente, com escopo por branch e trilha de quem leu o quê. Nunca aparecem no log — nem quando o job falha.

E se eu quiser sair?

Apague o flowbase.yml e revogue o app no seu provedor Git. Não tem nada para desinstalar.
