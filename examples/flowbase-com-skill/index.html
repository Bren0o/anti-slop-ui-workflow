Como funciona

Do commit ao deploy em um arquivo.

Você descreve os jobs; o FlowBase decide a ordem pelas dependências, cacheia o que se repete e roda em paralelo o que dá.

  1. Conecte o repositório

    GitHub, GitLab ou Bitbucket. Cada push abre um run; cada pull request recebe o status na própria PR.

  2. Escreva o flowbase.yml

    Jobs com needs viram um grafo. Sem needs, rodam em paralelo. Não existe uma segunda sintaxe para "workflows avançados".

  3. Cache sem configurar

    O FlowBase reconhece pnpm-lock.yaml, poetry.lock, go.sum, Cargo.lock e guarda a store de dependências entre runs, por branch.

  4. Leia o log, não o procure

    Quando um job falha, o trecho do log com a falha vem em primeiro lugar, com o arquivo e a linha do stack trace linkados para o commit.
